# 校园版咸鱼（校园二手交易平台）功能规格说明书 Spec

> 依据 `校园版咸鱼-需求文档.md` 全量整理，原始需求信息完整保留，使用中文描述。

## Why

高校学生有大量二手物品（教材、电子产品、生活用品等）交易需求，需要一个专属校园的轻量化平台，解决校外平台鱼龙混杂、交易距离远、诈骗风险高的问题，支持学生发布/求购二手商品、线下当面交易，同时方便管理员维护平台秩序。

## What Changes

- 新建校园二手交易 H5 平台（前端 H5 + 后端 API + 数据库）
- 实现六大核心功能：商品发布管理、求购管理、用户与认证、搜索筛选、互动与交易、平台管理
- 预留可扩展能力：AI 智能审核信息（可选）、校园闲置置换、公益捐赠、二手教材专区等模块
- 无复杂支付流程，主打线下当面交易
- 权限模型简单：仅管理员/普通学生两种角色

## Impact

- Affected specs: 无（全新项目，首个 spec）
- Affected code: 全新代码库（H5 前端、后端 API 服务、数据库建表脚本、AI 审核扩展接口）

## 1. 用户故事

### 1.1 学生（通用）

1. 作为学生，我希望能注册账号并登录，以便使用平台的全部功能。
2. 作为学生，我希望能提交"学号 + 学院"实名认证，以提升我的可信度。
3. 作为学生，我希望能查看实名认证的审核状态（待审核/已通过/已驳回）。
4. 作为学生，我希望能修改密码和个人资料，以便维护账号安全。
5. 作为学生，我希望遇到违规商品或用户时能一键举报，以维护平台秩序。

### 1.2 卖家

6. 作为卖家，我希望能发布二手商品（标题、价格、分类、新旧程度、校区、交易方式、图文描述），以便出售闲置物品。
7. 作为卖家，我希望能修改、上架/下架、删除我发布的商品，以便管理我的在售物品。
8. 作为卖家，我希望能收到商品留言通知并回复，以便解答买家疑问。
9. 作为卖家，我希望能浏览求购信息并接单沟通，以便主动匹配潜在买家。
10. 作为卖家，我希望与买家私聊并约定线下交易的时间地点，以便当面完成交易。

### 1.3 买家

11. 作为买家，我希望能按分类、价格区间、校区、新旧程度筛选商品，以便快速找到目标物品。
12. 作为买家，我希望通过关键词搜索商品并分页浏览，以便高效查找。
13. 作为买家，我希望查看商品详情（图文描述、发布者信息），以便判断是否购买。
14. 作为买家，我希望能对商品留言提问，以便在不加好友的情况下了解商品。
15. 作为买家，我希望能发布求购信息（物品名称、预算、期望成色），以便反向寻找货源。
16. 作为买家，我希望能与卖家私聊并发起订单，以便跟踪交易进度。
17. 作为买家，我希望订单状态在"待沟通 → 待交易 → 已完成"间流转，以便清晰掌握交易进展。

### 1.4 管理员

18. 作为管理员，我希望审核学生提交的实名认证（通过/驳回），以便保证用户真实性。
19. 作为管理员，我希望审核新发布的商品（通过/驳回），以便拦截违规内容。
20. 作为管理员，我希望处理违规举报（下架商品/警告用户/驳回举报），以便维护平台秩序。
21. 作为管理员，我希望查看、禁用/启用用户，以便封禁恶意用户。
22. 作为管理员，我希望管理商品分类（增删改），以便保持分类体系合理。
23. 作为平台，我希望能引入 AI 智能审核信息（文本/图片），以便自动拦截违规与涉诈内容，给平台装上智慧的大脑。

## 2. 功能列表（含执行步骤拆解）

### 2.1 用户与认证

**注册登录**
1. 用户输入手机号/学号、密码、昵称提交注册。
2. 系统校验唯一性（学号不可重复注册）与密码规则。
3. 注册成功后使用账号密码登录，服务端签发 JWT Token。
4. 后续请求携带 `Authorization: Bearer <token>`，过期需重新登录。

**实名认证**
1. 用户提交学号、学院、证明材料（如校园卡/学生证照片）。
2. 系统记录认证状态：`待审核`。
3. 管理员在后台审核：通过 → 用户获得"已认证"标识；驳回 → 填写驳回理由，用户可重新提交。

**个人信息**
1. 查看个人信息（昵称、头像、学院、认证状态等）。
2. 修改昵称、头像等非敏感信息。
3. 修改密码（需验证原密码）。

**Scenario: 实名认证通过**
- **WHEN** 管理员审核通过某学生的实名认证
- **THEN** 该学生资料展示"已认证"标识，其在商品页的可信度提升

### 2.2 商品发布管理

**发布商品（执行步骤）**
1. 卖家点击"发布"，填写标题、价格、选择分类、新旧程度、校区、交易方式，填写图文描述。
2. 上传商品图片（≤9 张，jpg/png/webp，单张 ≤5MB）。
3. 系统校验必填项与格式，提交后进入"待审核"状态（可配置为发布即可见）。
4. 管理员审核通过后商品在列表公开可见。

**管理商品（执行步骤）**
1. 卖家进入"我的发布"查看自己全部商品及状态。
2. 可执行：编辑（修改后重新进入待审核）、上架/下架、删除、标记已售出。
3. 删除/下架后商品不再对外可见；已有订单不受影响。

**Scenario: 发布商品成功**
- **WHEN** 卖家填写完整合法的商品信息并提交
- **THEN** 系统创建商品记录，状态为"待审核"，卖家在"我的发布"中可见

**Scenario: 越权修改商品被拦截**
- **WHEN** 用户 A 尝试修改用户 B 的商品
- **THEN** 系统返回 403，商品数据不变

### 2.3 求购管理

**发布求购（执行步骤）**
1. 学生填写求购信息：物品名称、预算、期望成色（可选校区/备注）。
2. 提交后求购信息进入求购广场列表（按时间倒序）。
3. 求购者可修改、关闭、删除自己的求购。

**卖家接单（执行步骤）**
1. 卖家浏览求购列表或按关键词筛选。
2. 点击"接单"，系统自动创建卖家与求购者的私聊会话（携带求购上下文）。
3. 双方私聊协商，可进一步创建订单。

**Scenario: 卖家接单**
- **WHEN** 卖家对某求购信息点击"接单"
- **THEN** 系统创建双方私聊会话并通知求购者，会话中自动携带求购信息

### 2.4 搜索筛选

**执行步骤**
1. 商品列表页提供筛选器：分类、价格区间（最低-最高）、校区、新旧程度。
2. 搜索框支持标题/描述关键词模糊搜索。
3. 多条件可叠加，结果按发布时间倒序（可选价格排序）。
4. 分页展示（默认每页 10 条），返回总数供前端渲染页码。
5. 任一筛选为"全部"时不参与过滤。

**Scenario: 组合筛选**
- **WHEN** 买家选择分类"教材"、价格 0-50 元、校区"东区"
- **THEN** 返回同时满足三个条件的商品分页列表，总数准确

### 2.5 互动与交易

**商品留言（执行步骤）**
1. 任何登录用户可在商品详情页发表留言（公开可见）。
2. 支持删除自己的留言；管理员可删除任意违规留言。
3. 留言按时间正序展示。

**私聊（执行步骤）**
1. 买家在商品详情点击"聊一聊"，系统创建（或复用）双方会话。
2. 双方在会话内发送文本消息（可扩展图片），按时间正序展示。
3. 会话列表按最新消息时间排序，显示未读提示。
4. 卖家通过私聊与买家约定线下交易时间与地点。

**订单跟踪（执行步骤）**
1. 卖家/买家在私聊达成一致后创建订单（关联商品或求购），初始状态"待沟通"。
2. 双方确认线下交易安排后，状态流转为"待交易"。
3. 线下当面完成交易后，任一方点击"确认完成"，状态流转为"已完成"。
4. 状态机：`待沟通 → 待交易 → 已完成`；任一未完成状态可"取消订单"（终态）。
5. 订单列表区分"我买到的 / 我卖出的"。

**Scenario: 订单正常流转**
- **WHEN** 卖家创建订单后双方确认交易并线下完成，买家点击"确认完成"
- **THEN** 订单状态依次经"待沟通 → 待交易 → 已完成"，商品标记为已售出

**Scenario: 非法状态流转被拦截**
- **WHEN** 请求将"已完成"订单改回"待交易"
- **THEN** 系统返回错误，订单状态保持"已完成"

### 2.6 平台管理

**商品审核（执行步骤）**
1. 管理员查看"待审核商品"列表。
2. 逐条查看图文详情，执行"通过"或"驳回（附理由）"。
3. 驳回后卖家可修改重新提交。

**举报处理（执行步骤）**
1. 用户对商品/用户/留言/求购提交举报（目标类型 + 目标 ID + 理由 + 证据图片）。
2. 管理员查看举报列表（待处理/已处理）。
3. 处理动作：下架违规商品、封禁/警告用户、删除违规留言、驳回举报；记录处理结果。

**用户管理（执行步骤）**
1. 管理员按关键词搜索用户列表。
2. 对违规用户执行"禁用"（无法登录/发布）或"启用"恢复。
3. 禁用用户时其"待审核/在售"商品自动下架。

**分类管理（执行步骤）**
1. 管理员新增/重命名/停用/删除分类。
2. 被商品引用的分类不可直接删除（需先迁移或提示）。

### 2.7 AI 智能审核（可扩展功能，可选）

**执行步骤**
1. 发布/留言/私聊消息产生时，将文本（及可选图片）送入审核通道。
2. 第一层：本地敏感词库过滤（违禁词、涉诈关键词）。
3. 第二层（可选）：调用外部 AI 审核服务，返回 `通过 / 疑似违规 / 拒绝` 建议。
4. `疑似违规` 进入管理员人工复核队列；`拒绝` 直接拦截并提示用户。
5. 审核接口独立封装，便于替换或关闭，不影响主流程。

**Scenario: AI 拦截涉诈文本**
- **WHEN** 用户发布包含涉诈敏感词的商品描述
- **THEN** 系统拦截发布并提示"内容包含违规信息，请修改后重试"，同时记录审核日志供管理员查看

## 3. API 接口设计

### 3.1 通用约定

| 项 | 约定 |
| --- | --- |
| Base URL | `/api/v1` |
| 认证方式 | `Authorization: Bearer <JWT>`；注册/登录/公开列表接口除外 |
| 统一响应 | `{ "code": 0, "message": "success", "data": { ... } }`；`code=0` 成功，非 0 为错误码 |
| 分页请求 | `page`（默认 1）、`pageSize`（默认 10，最大 50） |
| 分页响应 | `data: { "list": [...], "total": 0, "page": 1, "pageSize": 10 }` |
| 通用错误码 | 400 参数错误；401 未登录/Token 失效；403 无权限；404 资源不存在；409 状态冲突；429 请求过频；500 服务器错误 |
| 时间格式 | `yyyy-MM-dd HH:mm:ss`（东八区） |

### 3.2 数据模型概要

| 实体 | 关键字段 |
| --- | --- |
| user 用户 | id、学号 student_no、学院 college、昵称、密码哈希、手机号、角色(role: admin/student)、状态(正常/禁用)、头像、是否已认证、创建时间 |
| certification 实名认证 | id、user_id、学号、学院、证明材料图片、状态(待审核/已通过/已驳回)、驳回理由、审核人、审核时间 |
| category 分类 | id、名称、排序、状态(启用/停用) |
| goods 商品 | id、user_id、标题、价格、分类 id、新旧程度(全新/几乎全新/轻微使用/明显使用痕迹)、校区、交易方式(当面交易/宿舍自提/校内其他)、图文描述、图片列表、状态(待审核/在售/已下架/已售出/违规下架)、创建/更新时间 |
| want_buy 求购 | id、user_id、物品名称、预算、期望成色、校区、备注、状态(进行中/已成交/已关闭)、创建时间 |
| comment 留言 | id、goods_id、user_id、内容、状态(正常/已删除)、创建时间 |
| conversation 会话 | id、goods_id、want_id、买家 id、卖家 id、最后消息时间 |
| message 私聊消息 | id、conversation_id、sender_id、内容、类型(文本/图片)、创建时间 |
| order 订单 | id、订单号、goods_id、want_id、买家 id、卖家 id、状态(待沟通/待交易/已完成/已取消)、约定时间、约定地点、备注、创建/更新时间 |
| report 举报 | id、举报人 id、目标类型(商品/用户/留言/求购)、目标 id、理由、证据图片、状态(待处理/已处理/已驳回)、处理结果、处理人、创建时间 |
| audit_log 审核日志 | id、对象类型、对象 id、动作、AI 建议、人工结论、操作人、时间 |

## 5. 边界条件（异常情况）

### 5.1 注册与登录
- 学号已被注册：提示"该学号已注册"，不泄露他人信息。
- 密码不符合规则（长度/复杂度）：前端+后端双重校验并提示规则。
- 账号被禁用后登录：提示"账号已被禁用，请联系管理员"，拒绝签发 Token。
- Token 过期/伪造：返回 401，前端引导重新登录。

### 5.2 实名认证
- 重复提交认证（已待审核/已通过）：返回 409，提示当前状态。
- 证明材料过大或格式不支持：前端限制 + 后端校验，给出大小/格式要求。
- 认证被驳回：保留驳回理由，允许修改后重新提交。

### 5.3 商品发布与管理
- 必填项缺失/价格为 0 或负数/标题超长：后端逐项校验并返回具体字段错误。
- 图片超过 9 张、格式不支持、上传中断：中断的图片不进入商品数据。
- 快速重复点击提交：后端幂等/防重复，仅创建一条商品。
- 修改被驳回商品：重新进入"待审核"，不直接对外可见。
- 删除已有进行中订单的商品：商品标记删除但订单数据保留，订单流程可继续。

### 5.4 搜索筛选
- 关键词为空串/纯空格：忽略关键词，返回默认列表。
- 特殊字符与 SQL 注入字符：参数化查询，原样转义处理。
- 价格区间 min > max：返回 400 或空结果（约定为 400 + 提示）。
- 页码超出总页数：返回空 list 与正确 total，不报 500。

### 5.5 求购与接单
- 求购者本人接单自己的求购：拦截并提示。
- 预算为 0/负数：校验拦截。
- 已关闭/已成交的求购被接单：返回 409。

### 5.6 互动
- 留言为空/超长/含敏感词：拦截并提示；AI 审核命中"拒绝"时同样拦截。
- 给已下架/已删除商品留言或私聊：商品详情返回"已下架"，禁止新留言，历史留言隐藏。
- 非会话参与者读取/发送消息：返回 403。
- 向被禁用用户发送消息：发送失败并提示。
- 自己给自己的商品留言：允许但可标注"发布者"身份，不创建自聊会话。

### 5.7 订单
- 对已售出/已下架/待审核商品创建订单：返回 409。
- 同一商品重复创建进行中订单：拦截。
- 取消已完成订单：返回 409。
- 双方并发操作状态（如同时确认完成）：以数据库乐观锁/状态条件更新保证只生效一次。
- 约定时间为过去时间：提示检查时间。

### 5.8 举报与管理
- 重复举报同一目标且仍在待处理：不重复创建，提示已受理。
- 举报理由为空/超长：校验拦截。
- 删除仍被在售商品引用的分类：返回 409，提示先迁移商品或改用"停用"。
- 禁用用户：其待审核/在售商品自动下架；其进行中订单由对方取消或等待线下处理（记录处理结果）。
- 管理员驳回举报需填写处理说明，留痕审计。

### 5.9 通用
- 网络失败/服务不可用：前端统一错误页与重试提示，不出现白屏。
- 上传弱网重试：同一文件重复上传返回同一 URL（幂等）。
- 接口限流：登录、发布、留言、发消息限频（如 10 次/分钟），超限返回 429。
- 请求体过大/非法 JSON：返回 400。

## 6. 非功能性需求

### 6.1 性能
- 核心接口 P95 响应时间 ≤ 800ms；商品列表在 1 万级数据量下 ≤ 1s。
- 支持 ≥ 500 并发在线用户（校园规模）；列表查询建立必要索引（分类/校区/状态/价格/创建时间）。
- 图片走静态资源/对象存储 + CDN 缓存；列表页图片使用缩略图。

### 6.2 安全
- 全站 HTTPS 传输；密码使用 bcrypt/argon2 加盐哈希存储。
- JWT 认证，设置合理有效期（如 2h）+ 退出黑名单；防重放。
- 防 SQL 注入（参数化查询）、防 XSS（输出转义/CSP）、防 CSRF。
- 水平与垂直越权双重校验；敏感操作（审核、封禁、删除）写审计日志。
- 用户敏感信息脱敏展示（学号如 `2021****123`），手机号仅本人可见。
- 登录/发布/留言/消息接口限流，防刷防灌水。
- 上传文件校验类型与大小，重命名存储，禁止执行权限。

### 6.3 兼容性与可用性
- **移动端 H5 优先**：响应式布局，适配 iOS/Android 主流机型及微信内置浏览器，随时随地发布和浏览。
- 桌面浏览器可正常使用；核心流程兼容 Chrome/Safari/微信。
- 核心功能可用性 ≥ 99.5%；所有异常均有友好中文提示，无裸露堆栈。

### 6.4 可维护性与可扩展性
- 权限模型简单：仅管理员/普通学生两种角色（RBAC 结构预留扩展位）。
- 模块化设计，预留扩展模块：校园闲置置换、公益捐赠、二手教材专区。
- AI 智能审核以独立通道接入（本地敏感词 + 可选外部 AI 服务），可开关、可替换，不影响主流程。
- 无在线支付流程，规避金融合规复杂度；交易以线下当面为主。

### 6.5 数据
- 数据库每日自动备份，恢复演练可用。
- 关键业务数据（订单、审核、举报）逻辑删除优先，保留追溯能力。
- 审核日志（人工 + AI）保留 ≥ 180 天。

## ADDED Requirements 汇总（EARS 摘要）

### Requirement: 用户与认证
系统 SHALL 提供学生注册登录（JWT）、学号+学院实名认证提交与管理员审核、个人资料与密码维护能力。

### Requirement: 商品发布管理
系统 SHALL 支持二手商品全字段（标题、价格、分类、新旧程度、校区、交易方式、图文描述）的增删改查，仅发布者可修改/删除自己的商品。

### Requirement: 求购管理
系统 SHALL 支持发布求购信息（物品名称、预算、期望成色）并支持卖家接单后自动建立私聊会话。

### Requirement: 搜索筛选
系统 SHALL 支持按分类、价格、校区、新旧程度组合筛选与关键词搜索，并分页返回。

### Requirement: 互动与交易
系统 SHALL 支持商品留言、买卖双方私聊、线下交易约定与订单状态跟踪（待沟通/待交易/已完成，可取消）。

### Requirement: 平台管理
系统 SHALL 为管理员提供商品审核、违规举报处理、用户管理与商品分类管理能力。

### Requirement: AI 智能审核（可扩展）
系统 SHOULD 提供可选的 AI 智能审核通道（敏感词 + 外部 AI 服务），对发布/留言/私聊内容给出 通过/疑似违规/拒绝 建议，并支持人工复核。
